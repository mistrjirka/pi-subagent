# Runtime boundaries

- `index.ts` owns the extension-level registry, parent message transport, recovery state, monitoring tools and shutdown; `spawn-tool.ts` registers and executes the spawn tool using explicit typed ports and the existing `spawn-session.ts` state machine.
- `spawn-identity.ts` builds a strictly named child environment with the required tree ID, delegation allowlist and ancestor chain; `tree-telemetry.ts` exports the typed parent telemetry port.
- `discovery-tools.ts` owns read-only active-agent listing and saved-session recovery tool registration. `parent-delivery.ts` owns model-turn boundaries and tool-result error/notification transformations. Their order preserves receipt-first completion delivery.
- `tree-telemetry.ts` owns nested-child event tracking and `supervision-reminder.ts` generates bounded, current-session-checked supervision messages. `index.ts` remains the root process bootstrap and spawn lifecycle entrypoint.
- `message-router.ts` owns hop-by-hop direct-child delivery, parent status transport, and the parent message fallback. `MessageRouter` holds the Pi and registry ports. It does not own child lifetime or announcements.
- `control-tools.ts` registers `agent_stop`, `agent_send`, and `ask_parent` with the same schema-derived arguments. It injects typed actions for message routing, status updates, tree removal, and recovery retirement instead of reading extension-global state.
- `tool-params.ts` defines Pi tool schemas and derives argument types with TypeBox `Static`. The `agent_spawn` schema is different for root and child processes. The single explicit `SpawnParams` cast at the registered handler is the boundary for that runtime-dependent choice; other tool handlers use inferred schema types.
- `spawn-coordinator.ts` makes an admission decision before launching a child. It resolves the named profile and model, enforces delegation/background policy, and claims any explicitly requested recovery. It takes a narrow `RecoveryPort` and injectable profile/model services. It never renders a card or starts a process.
- `spawn-result.ts` presents background, completed, failed, stopped, and `ask_parent` outcomes. It builds the exact tool result and optional tree-removal decision. The caller still owns recovery-lease changes, tree mutations and the live UI update. No notification or process lifecycle policy changes.
- `spawn-session.ts` owns foreground, background, abort and resident lifetime transitions once an `AgentProcess` exists. `agent-process.ts` owns the one child Pi RPC process and translates its messages to domain events.
- `agent-process-contracts.ts` defines typed process inputs and completion results. `agent-activity-fold.ts` owns ordered thinking/text/tool excerpts and presentation callbacks. `agent-settlement-latch.ts` remembers each turn's settlement, including notifications that arrive before a waiter attaches. `agent-process.ts` keeps RPC lifecycle and parent-question handling but no longer owns the presentation fold or settlement waiter set.
- `child-event-writer.ts` owns `events.jsonl` creation, append/coalescing, assistant-message boundaries, and the file-size cap. `external-control.ts` remains the status and steer/stop bridge, with the same exported compatibility types and public event methods.
- `agent-telemetry.ts` owns completed-turn count, executed-tool count, last activity and current context usage. `external-control.ts` publishes this bounded snapshot in `status.json`. It does not scan a full Pi session or store token histories. `message_end` with assistant usage updates the context window; a tool-result end clears an active tool without double-counting.
- `registry.ts` owns per-parent child lifecycle, routing, waiting and completion deduplication. It records substantive child-to-parent messages **when delivered** (not when merely queued), per child task. A subsequent completion after such a delivered update is passive, with no second model wake. Unread completions lacking a delivered update remain proactive. These receipts reset on each accepted new task, and urgent `ask_parent` remains immediate. `notification.ts` constructs the model-visible completion and display card; a passive notification is saved but does not initiate a model request. The UI should not reimplement registry policy.
- `agent-wait-coordinator.ts` owns child wait subscriptions, completion resolution, parallel-message wakeups, timeout/abort cleanup and session-shutdown unblocking. It never decides whether a completion should wake the parent model.
- `registry-contracts.ts` owns public registry types and ancestor parsing; `registry-roster.ts` owns pure active-roster and target-hint projections. `supervision.ts` owns fallback reminder timers and explicit wait pauses. `agent-name-allocator.ts` reserves ancestor names; `diagnostic-dedup.ts` bounds repeated delivered diagnostics. These services do not wake model turns or change the v0.5.18 notification policy.
- `wait-input.ts` listens to the optional accepted `input_queued` hook. Same-session user steering releases only active wait controllers. It never retains input for later waits, aborts the parent turn, stops children, or reads transcripts. Explicit parent cancellation keeps its existing error behavior. Older Pi hosts can register the hook without emitting it.
- `monitoring-tools.ts` owns the `agent_wait` and `agent_inspect` tool definitions and response formatting. It receives the parent-owned unread transcript cursor through a narrow typed callback, so both commands still advance exactly one shared cursor and preserve `agent_wait` message/completion delivery rules.
- `index.ts` wires the above services to Pi extension hooks. Its remaining orchestration is a future extraction seam; changes should follow contract tests rather than rewrite lifecycle and delivery simultaneously.

## Status protocol

`status.json` retains version 1. New optional, nonnegative fields `turnCount`, `toolCount`, `windowTokens` and `lastActivityAt` record completed assistant messages, unique started executions, most recent model input window including cache tokens, and genuine activity timestamp (not heartbeat). Legacy consumers may ignore these fields; new consumers use them instead of reading session-file tails. An idle child can remain resident and have nonzero counters.

## Type safety

Validate untrusted RPC and filesystem records at their ingress. Preserve typed domain values after that. Prefer narrow structural dependencies to casting a whole service to `unknown` and back. Keep DOM/TUI state out of business policies.
